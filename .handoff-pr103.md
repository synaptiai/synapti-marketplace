### Scope to build

Three test suites at minimum:

1. **`plugins/flow/tests/aggregate-findings-ledger.test.sh`** — unit tests for the helper.
   - Synthetic FLOW_REVIEW_CYCLE + FLOW_RESOLUTION_CYCLE markers as fixtures.
   - Cases to cover: jq-missing fallback, gh-failed fallback, empty body, partial fetch, trust-list cascade (HIGH_RISK warning, invalid array, valid array), `safe()` sanitization (backticks, `$`, non-printable bytes, length cap), ID/priority allowlist, marker scoping to HTML comment only (the F16 regression), cumulative-marker semantics (cycle 3 = cycle 1 ∪ cycle 2), circuit breaker after 5 consecutive failures, sentinel-file behavior across pipe-induced subshells.

2. **`plugins/flow/tests/cascade-resolve.test.sh`** — unit tests for the cascade helper.
   - Cases: tilde expansion (`~`, `~/path`, non-tilde strings), compact mode (no tilde expansion), `$HOME=""` warning + `/nonexistent` fallback, `--default` value tilde expansion, missing jq, malformed JSON parse error, all 4 cascade tiers (write to tmp files), precedence order.

3. **`plugins/flow/tests/command-frontmatter.test.sh`** — static lint over `commands/*.md`.
   - Every `!` block ends with `true`.
   - Every `$ARGUMENTS` in `!` blocks is either quoted (`"$ARGUMENTS"`) or used in `case` validation.
   - `allowed-tools` references match actual `Bash(...)` invocations in the file (no dead patterns, no missing patterns).
   - HTML comment markers in references/docs are well-formed.

### Recommended approach

Use a single test runner script at `plugins/flow/tests/run.sh` that:
- Sets up isolated `HOME=$(mktemp -d)` for cascade tests
- Mocks gh via a stub script on `$PATH` for ledger tests (so we don't make real API calls)
- Reports pass/fail counts with file:line citations
- Returns non-zero on any failure

Add a GitHub Actions workflow at `.github/workflows/flow-tests.yml` that runs on PRs touching `plugins/flow/**`.
